### The two outside services

| Service | Address | Used for | Trust |
|---|---|---|---|
| MP3Quran v3 | `https://www.mp3quran.net/api/v3` (`/reciters`, `/suwar`, `/riwayat`, `/radios`, `?language=ar`) | lists and the audio file addresses (`moshaf.server` + 3-digit surah + `.mp3`) | stable |
| MP3Quran v4 | `https://api-staging.mp3quran.net/v4` (`word-timings?include=text`, `ayah-timings`, `surahs/{n}/text`) | the text and the word/ayah timings | **staging: can stop any day (REL-07)** |

The v4 recitation code is the path after `/audio/` in the v3 `moshaf.server`. About 266 of 297 recitations have
timings. A word timing row is `[ayah, position, startMs, endMs, occurrence]`. Ayah 0 is the basmalah.

### Rule for REL-07 (the page must work without v4)

- Every request goes through `timedFetch` (8 s). `getSurahSync` never throws: any failure gives `level: 'none'`.
- With `level: 'none'` the reader still plays the audio and shows the line
  "النص المتزامن غير متاح لهذه التلاوة الآن." No error screen.
- Keep a successful v4 answer in `sessionStorage` under `quran-sync:<code>:<surah>` (try/catch around every access;
  skip storing when the JSON is over 400 kB).
- The v4 base address comes from one constant `QURAN_SYNC_BASE` in `quranApi.ts`, so a move to a production
  address is a one-line change. Add the comment: "staging address; check https://mp3quran.net/api for a stable one".

### Build these (each under 350 lines; view in components, behaviour in hooks)

1. `src/pages/quran/QuranPage.tsx`, route `/quran`: three tabs "القرّاء", "السور", "الإذاعات".
   - القرّاء: `RecitersList` with a search box (use `normalizeArabic`) and a riwaya filter; a reciter opens `/quran/reciter/:id`.
   - السور: `SurahGrid`; a surah opens the reader with the remembered reciter (`preferredChoice`), else the first
     reciter whose moshaf has that surah.
   - الإذاعات: `RadiosList`; a radio plays through the site's audio engine as a live track (no seek bar).
2. `src/pages/quran/ReciterPage.tsx`, route `/quran/reciter/:id`: the reciter's name, a moshaf chooser when they
   have more than one, the surahs of that moshaf (`moshafSurahs`), each with "استماع" and "قراءة مع الصوت".
3. `src/pages/quran/reader/`, route `/quran/read/:reciterId/:moshafId/:surah`:
   - `useSurahSync.ts`: loads `getSurahSync`, exposes `{ level, text, words, ayahs, loading }`.
   - `useHighlight.ts`: one `requestAnimationFrame` loop while playing; reads the time from `useAudio()`; finds the
     word with `wordIndexAt` (or the ayah with `ayahAt` when `level === 'ayah'`); changes the highlight by
     toggling a class on DOM nodes kept in a `ref` array. **It must not call `setState` per frame.**
   - `ReaderText.tsx`: renders the words once (`memo`), each word a `<span data-i>`; one click handler on the
     container seeks the audio to that word's start (`seek(startMs / 1000)`).
   - `ReaderControls.tsx`: play/pause, previous/next surah, speed (0.75, 1, 1.25, 1.5), "تكرار الآية" (when on, at
     the end of the current ayah seek back to its start), font size (2 steps up/down, remembered in `localStorage`).
   - `QuranReader.tsx`: composes them; scrolls the active ayah into view (`scrollIntoView({ block: 'center', behavior: 'smooth' })`)
     only when the ayah changes and the visitor did not scroll by hand in the last 4 seconds.
   - The basmalah: when `hasSeparateBasmalah` is true show it as its own line above ayah 1.
   - `prefers-reduced-motion`: no smooth scrolling.
4. Routes in `src/routes/AppRoutes.tsx` + `lazyPages.ts` (all three lazy). Links: top bar and side menu
   ("القرآن الكريم"), and the footer.
5. `vercel.json` Content-Security-Policy: add `https://www.mp3quran.net https://api-staging.mp3quran.net` to
   `connect-src`, and `https://*.mp3quran.net` to `media-src` (the audio servers are `serverN.mp3quran.net`).
   Read one real `moshaf.server` value to confirm the host pattern before writing it.
6. SEO: `scripts/prerender.mjs` gets one page for `/quran` (title "القرآن الكريم | استماع وقراءة"), and
   `scripts/generate-sitemap.mjs` lists `/quran`. Reciter and reader pages are **not** in the sitemap.
7. Playing a surah uses the site's audio engine (`useAudio().play(track, startAt)`), so the bottom player and the
   lock-screen controls work; do not create a second `Audio` element.
