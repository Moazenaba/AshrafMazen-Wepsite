# إصلاح الأعطال

ابدأ دائماً بـ: **لوحة الإدارة ← صحة الموقع والأخطاء ← إعادة الفحص**. تقول لك أي جزء معطّل وما تفعله. وللفحص من سطر الأوامر: `npm run health`.

## ملخص سريع: العرَض ← السبب ← الحل

### الرفع
| العرَض | السبب الأرجح | الحل |
|---|---|---|
| «تخزين الملفات غير مُفعّل على هذا الخادم» | متغيرات R2 غير موجودة في Vercel | أضف `R2_ACCOUNT_ID` و`R2_BUCKET` و`R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` و`SUPABASE_URL` و`SUPABASE_ANON_KEY` ثم أعد النشر |
| «منع المتصفح الرفع إلى Cloudflare R2» | لا توجد قاعدة CORS على الحاوية | R2 ← الحاوية ← Settings ← CORS Policy ← الصق `docs/r2-cors.json`. وأضف دومين الموقع إن لم يكن فيه |
| «رفض التخزين الملف (403)» | صلاحية التوكن ناقصة، أو الرابط انتهى | تأكد أن التوكن Object Read & Write على نفس الحاوية، وأعد المحاولة |
| «هذه العملية للإدارة فقط» | انتهت جلسة الدخول | سجّل الخروج ثم الدخول |
| رفع ملف كبير يفشل | حدّ الحجم | الحدود: صوت ٥٠٠MB، كتاب ٢٠٠MB، غلاف ٥MB، لوجو ٢MB |

### عرض الملفات
| العرَض | الحل |
|---|---|
| الصوت أو الكتاب لا يفتح | افتح `/api/r2?file=<المسار>` يدوياً. إن رجع 501 فالمتغيرات ناقصة. إن رجع 400 فالمسار خارج مجلدات الموقع |
| فتح الصفحة مباشرة يعطي 404 على Vercel | تأكد أن `vercel.json` موجود في جذر المشروع المنشور |
| الصفحة بيضاء بعد تحديث الموقع | الزائر على نسخة قديمة. الموقع يعيد التحميل تلقائياً مرة. إن استمر: تحديث قسري (Ctrl+Shift+R) |

### البيانات
| العرَض | الحل |
|---|---|
| تاب الإحصائيات يقول «admins only» أو دالة غير موجودة | شغّل `2026-11-04-analytics.sql`، وتأكد أنك داخل بحساب أدمن |
| تاب الطلبات يعطي خطأ | شغّل `2026-11-04-hardening-and-contributions.sql` |
| حفظ درس يفشل | افتح Console في المتصفح. أغلب الأسباب: جلسة منتهية، أو سياسة `is_admin()` لا تجد المستخدم في جدول `admins` |
| لا تظهر الفيديوهات الجديدة من القناة | دالة `/api/youtube-library` لا تعمل، أو لم يمضِ ٦ ساعات (تخزين مؤقت). الموقع يعرض النسخة المضمّنة حينها |
| فيديو اختفى من الموقع | الأدمن أخفاه من «فيديوهات القناة». أظهره من هناك |
| الأقسام لا تظهر في الرئيسية | القسم بلا سلاسل فيها دروس منشورة لا يظهر للزوار |

### طلبات الزوار والإحصائيات
| العرَض | الحل |
|---|---|
| «الطلبات المنتظرة وصلت الحد الأقصى» | راجع الطلبات في الإدارة (قبول أو رفض ثم حذف). السقف ٥٠٠ منتظر |
| الأرقام صفر | طبيعي قبل أول زائر. جرّب فتح الموقع في نافذة أخرى وانتظر ٢٠ ثانية |
| «على الموقع الآن» أقل من الواقع | يُحسب من أرسل نبضة خلال دقيقتين. من يترك الصفحة في الخلفية لا يُحسب |

## تجربة محلية لا تستطيع الاتصال بـ Supabase من دوال `api/`

إن ظهر في سجل السيرفر `unable to verify the first certificate` فالمشكلة في شهادات الشبكة على جهازك (بروكسي أو مضاد فيروسات)، وليست في الموقع. شغّل `npm run dev` من طرفية عادية، أو اضبط `NODE_EXTRA_CA_CERTS`.

## أوامر الفحص

```bash
npm run check                               # الأنواع + البناء
npm run health                              # القاعدة والصلاحيات وR2
npm run dev                                 # ثم في طرفية أخرى:
npm run smoke http://localhost:3000         # كل صفحة وكل دالة
npm run smoke https://دومين-الموقع           # نفس الفحص على الموقع المنشور
```

## استعادة الأشياء

- **حذفتَ كتاباً بالخطأ:** الملف حُذف من R2 أيضاً. أعد رفعه وأضفه من جديد.
- **أخفيتَ فيديو بالخطأ:** تاب «فيديوهات القناة» ← زر العين ← حفظ.
- **لا يعمل شيء بعد تعديل:** النسخة الأخيرة المنشورة على Vercel تبقى محفوظة؛ من **Deployments** اختر النشر السابق ثم **Promote to Production**.
- **نسخة احتياطية للبيانات:** في Supabase ← Database ← Backups، أو صدّر الجداول `lessons` و`series` و`categories` و`site_settings` من **Table Editor ← Export**.

## تغيير كلمة سر أو مفتاح

| ما | كيف |
|---|---|
| كلمة سر الأدمن | لوحة الإدارة ← صحة الموقع والأخطاء ← تغيير كلمة المرور |
| مفاتيح R2 | Cloudflare ← R2 ← Manage API Tokens ← Roll، ثم حدّث `.env.local` ومتغيرات Vercel وأعد النشر |
| كلمة سر قاعدة بيانات Supabase | Project Settings ← Database ← Reset database password. الموقع لا يستخدمها، فلن يتأثر |

## الموقع لا يمر فحص المراقبة

المراقبة تعمل داخل مهمة `sync-youtube` كل نصف ساعة وتفشل المهمة (فيصلك بريد من GitHub) إذا فشل بند من `scripts/smoke-test.mjs`. كل بند وما يعنيه موجود في `docs/RUNBOOK.md`.

### صفحة الموقع تفتح لكن دوال `api/` لا تجيب

تحقق في Vercel من آخر نشر ومن سجل الدوال، ثم في تبويب «صحة الموقع والأخطاء» من «سجل الأخطاء». إن كان جدول `error_events` غير موجود شغّل `docs/migrations/2026-11-16-error-events.sql`.

### فحص الترويسات الأمنية فشل

افتح `vercel.json` وتأكد أن `Content-Security-Policy` و`Strict-Transport-Security` ما زالا في قسم `headers`، ثم أعد النشر.
