# ملفات قاعدة البيانات (Supabase)

تُشغَّل في **Supabase ← SQL Editor**، وكلها آمنة عند إعادة تشغيلها (idempotent).

| الترتيب | الملف | ما يفعله |
|---|---|---|
| 1 | `2026-11-04-hardening-and-contributions.sql` | يقفل جدول `admin_users` القديم (كان مكشوفاً)، وينشئ جدول `submissions` لطلبات الزوار مع صلاحياتها وسقف ٥٠٠ طلب منتظر |
| 2 | `2026-11-04-analytics.sql` | جداول ودوال الإحصائيات: من على الموقع الآن، والمشاهدات، وساعات المتابعة، وكل محتوى على حدة |
| 4 | `2026-11-05-concurrent-saves.sql` | دالة `save_setting_if_unchanged`: تمنع ضياع تعديل لو مديران حفظا الكتب أو فصول الدروس في نفس اللحظة. الموقع يعمل بدونها ويستعملها تلقائياً بعدها |
| 5 | `2026-11-16-error-events.sql` | جدول `error_events` (سجل أخطاء الموقع يقرأه الأدمن فقط) وسقف يومي لدالة `record_event` المفتوحة. الموقع يعمل بدونه، ويظهر في تبويب «البيانات والتكامل» تنبيه بتشغيله |
| 3 | `2026-11-05-security.sql` | يكتب صلاحيات الجداول الأساسية في ملف (الزائر يقرأ فقط، والمسودات للأدمن)، ويخفي الكتب المسودة، ويمنع إضافة الطلبات إلا عبر `api/submit`. **قبل تشغيله:** ضع `SUPABASE_SERVICE_ROLE_KEY` في Vercel وانشر، وإلا يتوقف نموذج «شارك» |

**الجداول الأساسية** (`categories` و`series` و`lessons` و`admins` و`site_settings` و`social_links` ودالة `increment_lesson_views`) أُنشئت في المرحلة الأولى للمشروع ولا ملف لإنشائها هنا. صلاحياتها ودالة `is_admin` صارت في الملف 3. لو أنشأت مشروع Supabase جديداً من الصفر فستحتاج إنشاءها أولاً (راجع الأعمدة في `src/types.ts`).

## اختبار سريع بعد التشغيل

```bash
npm run health
```

يجب أن تكون كل النتائج `PASS`، وخصوصاً بنود «protected from visitors».

## جدول `admin_users`

جدول قديم (من خادم Express محذوف) فيه عمود `password` وصف واحد. الموقع **لا يستخدمه**، والملف الأول يقفله. الأفضل حذفه نهائياً بعد أن تتأكد أنك لا تحتاجه:

```sql
drop table public.admin_users;
```
